# p2gles: этап 0, тонкий рендерер OpenGL ES 3.0

Отдельный бинарь `p2gles` (winit + glutin/EGL + glow), контекст **OpenGL ES 3.0** (`#version 300 es`).
Сцену берёт из `p2view::scene::build_scene` (парсинг не переписывался), `gpu_bc: false` (DXT декодируется в RGBA8 уже в p2view, мипы готовые).
Существующую игру не трогали: только новый крейт и строка в workspace `Cargo.toml`.

## Как собрать и запустить

```
export CARGO_TARGET_DIR=../host-target
cargo +stable build --release -p p2gles
DISPLAY=:0 $CARGO_TARGET_DIR/release/p2gles --map suburbs-3 --bench 20 --res 800x480
DISPLAY=:0 $CARGO_TARGET_DIR/release/p2gles --map suburbs-3 --screenshot out.png
DISPLAY=:0 $CARGO_TARGET_DIR/release/p2gles --map estates          # интерактивно: WASD, Q/E, Shift, мышь, Esc
```
Опции: `--game DIR`, `--map`, `--res WxH`, `--cam x,y,z,yaw,pitch` (единицы Unreal, как P2GAME_CAM_AT), `--bench СЕК`,
`--screenshot f.png`, `--fog start,end` (метры), `--chunk МЕТРЫ` (по умолчанию 48), `--no-cull`, `--vsync`.

Примечание по сборке на этом ПК: нет dev-пакетов alsa/libudev (sudo нет), поэтому сборка шла с фиктивными
`alsa.pc`/`libudev.pc` в `PKG_CONFIG_PATH`, указывающими на системные `.so.2`/`.so.1` (headers alsa-sys не нужны).

## Что сделано
- Запечённая геометрия: BSP (по треугольникам), статические меши (преобразование зашито в вершины), слои террейна
  разбиты на пространственные чанки 48 м и сгруппированы по ключу (текстура, лайтмап, alpha-карта, blend, two-sided, режим света).
  Все вершины в одном VBO (32 байта/вершина) и одном u32 IBO, один VAO. suburbs-3: 499k вершин, 445k треугольников, 20 МБ, 1844 записи отрисовки.
- Отсечение по чанкам: пирамида видимости (AABB) + дальность до конца тумана (far-плоскость = fog_end*1.05).
- Шейдер один (VS+FS, ~40 строк): текстура * свет, всё в гамма-пространстве как UE2.
  BSP = tex * (lightmap*2); статмеши = tex * (запечённый vertex light + ambient зоны*0.65 + glow*0.5) * 2 (формулы из spawn.rs/baked.rs, но без pow 2.2: sRGB-округление);
  террейн = tex * запечённый vertex light, слои 1+ смешиваются по alpha-карте (R8, через uv_b), без света = константа 0.75.
- Блендинг: Opaque, Masked (discard alpha<0.5), Translucent, Modulate, Additive, Darken. Проходы: opaque, masked, splat, blended (сортировка дальше-ближе по центру чанка).
- Линейный туман из SceneData (цвет тумана = цвет очистки), `--fog` для переопределения. Мипмапы + анизотропия 8x при наличии расширения.
- Режимы: интерактивный fly-камера, `--bench`, `--screenshot` (PNG).

## Измерения (этот ПК: Quadro RTX 3000, NVIDIA 595, ES 3.2 драйвер, контекст запрошен 3.0, 800x480, vsync off, из точки спавна, 20 с)
Среднее wall-clock за окно 5 с, включая swap:

| карта | мс/кадр | fps | draw calls/кадр | треугольники/кадр | всего записей / треугольников в карте |
|---|---|---|---|---|---|
| suburbs-3 | 0.30-0.36 | ~2700-3300 | 240 | 95 197 | 1844 / 445 187 |
| estates | 0.27-0.29 | ~3500-3750 | 187 | 56 734 | 1248 / 294 303 |
| suburbs-3 без отсечения (`--no-cull`, 10 с) | 0.96 | ~1050 | 1844 | 445 187 | |

Для сравнения: порт на Bevy ~2400 draw. Здесь 240/187. Время на сильной карте мало о чём говорит для Mali-G31 (там важны
число draw call, заполнение и пропускная способность), реальный ответ даст только запуск на коробке (этап не делался, к ней не обращались).
Загрузка: build_scene ~0.6-1.0 с, bake ~0.1-0.4 с, заливка текстур ~0.2 с.

## Чего нет / известные расхождения
- Нет неба (sky zone BSP/инстансов), только цвет очистки. Нет декораций террейна (`data.deco`: трава/камни).
- Нет UV-анимации материалов (TexPanner/Rotator) и анимированных текстур (frames); нет проекторов, подвижных акторов (movers стоят в кадре 0), персонажей.
- Нет зонального отсечения (portals/zones) и `cull_distance` инстансов (только туман/frustum на уровне чанков).
- Динамический свет не реализован: статмеши без запечённого света и BSP с «чёрным» лайтмапом получают константу 0.75.
- Glass (порядок стекла после листвы) не учтён; прозрачные чанки сортируются по центру AABB, возможны артефакты.
- Туман смешивается в гамма-пространстве (в Bevy в линейном): небольшое отличие цвета.
- Гамма: pow(…,2.2) заменена умножением в гамма-пространстве; визуально совпадает, точные числа не сверялись пиксель в пиксель.
- Не проверена работа на Mesa/Panfrost и GLES 3.1 на целевом железе; текстуры RGBA8 без сжатия (на Mali-G31 стоит перейти на ETC2/ASTC: 365 текстур в RGBA8 это сотни МБ).
- Время кадра на ПК измерялось только wall-clock; CPU-стоимость кадра отдельно не профилировалась.

## Что нужно для этапа 1 (рендерер вместо Bevy в игре)
1. Вынести `renderer.rs` в библиотеку: API `Scene::new(gl, &SceneData)`, `render(view_proj, cam)`; убрать `winit`-часть из бинаря.
2. Динамические акторы (персонажи, оружие, пикапы, физ. объекты): скелетная анимация/skinning в вершинном шейдере (или CPU-скиннинг в стриминговый VBO), отдельный проход.
3. Интеграция с p2game: movers/двери (динамические трансформы поверх запечённых чанков: вынести такие инстансы из слияния), показ/скрытие акторов, `ZoneGraph`.
4. Небо (отдельный проход с камерой из `sky.origin` только с вращением), декорации (инстансинг, `glDrawElementsInstanced` в ES 3.0), UV-анимация (униформа смещения на материал/draw).
5. Эффекты p2fx (частицы, проекторы-декали, вспышки), HUD/p2canvas (2D поверх), динамические источники света (хотя бы ограниченное число на вершину/пиксель).
6. Сжатые текстуры ETC2/ASTC (конвертация при загрузке или кэш), тестовый прогон на Panfrost GLES 3.1.
7. Ввод/окно: заменить Bevy-цикл на winit+glutin, перенести `cam_override`, скриншоты, захват курсора.
